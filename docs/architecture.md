# معماری سیستم — پیمانه (Peimaneh)

> نسخه اولیه معماری برای فاز‌های نقشه‌راه ([[docs/roadmap.md]]). هدف: طراحی‌ای که از MVP تک‌کاناله تا نسخه چندکاناله/چندزبانه بدون بازنویسی کامل رشد کند.

---

## اصول طراحی
1. **Human-in-the-loop اجباری** — هر خروجی که تعهد تجاری ایجاد می‌کند (قیمت خارج از سیاست، تخفیف، تاریخ تحویل قطعی) باید از Guardrail عبور کند و در حالت پیش‌فرض نیاز به تأیید انسان دارد.
2. **Channel-agnostic core** — منطق مکالمه/مذاکره از کانال ورودی (واتساپ/ایمیل/لینکدین) جدا است؛ افزودن کانال جدید فقط یک adapter جدید می‌خواهد.
3. **Policy as data, not code** — سیاست‌های شرکت (کف قیمت، شرایط پرداخت، ظرفیت) در قالب config/داده ذخیره می‌شوند تا مدیر بازرگانی بدون دیپلوی بتواند تغییرشان دهد.
4. **State per thread** — هر مکالمه (thread) یک state machine مستقل با مرحله مشخص دارد؛ هیچ تصمیمی بدون دانستن «این مکالمه الان کجاست» گرفته نمی‌شود.
5. **Auditability** — هر پیشنهاد AI، تصمیم انسانی (تأیید/رد/ویرایش) و دلیل، لاگ می‌شود — هم برای اعتماد‌سازی و هم برای یادگیری بعدی سیستم.

## اجزای اصلی

### ۱. Channel Adapters
مسئول دریافت پیام خام از هر کانال و نگاشت آن به یک فرمت داخلی یکسان (`Message{thread_id, sender, channel, text, timestamp, attachments}`) و برعکس برای ارسال.
- فاز ۱: فقط ورودی (read-only)، ارسال دستی توسط انسان.
- فاز‌های بعد: امکان ارسال مستقیم پیش‌نویسِ تأییدشده از داشبورد.

### ۲. Conversation Engine
- **NLU**: تشخیص نیاز (قیمت/نمونه/شرایط پرداخت/حمل/اعتمادسازی)، تشخیص زبان، تشخیص سطح جدیت.
- **Summarization**: خلاصه کوتاه هر thread برای نمایش در داشبورد.
- **Multilingual NLG**: تولید پیش‌نویس پاسخ با لحن مناسب بازار هدف (رسمیت، مستقیم/غیرمستقیم بودن، اصطلاحات تجاری رایج آن بازار).

### ۳. Policy & Guardrail
منبع حقیقت سیاست‌های شرکت. هر پیشنهاد قیمت/شرط از Conversation Engine قبل از تبدیل به پیش‌نویس نهایی از این لایه عبور می‌کند:
- اگر داخل سیاست بود → پیش‌نویس آماده می‌شود، وضعیت `ready_to_send`.
- اگر خارج از سیاست یا مربوط به کشور/مشتری حساس بود → وضعیت `needs_human_approval` با دلیل مشخص.

### ۴. Negotiation Orchestrator
- نگه‌داری state هر thread طبق مراحل مذاکره.
- Follow-up Scheduler: تشخیص «چند روز پاسخی نیامده» یا «قرار بود پیگیری شود» و ساخت یادآوری.
- Escalation Rules: قوانین سخت‌گیرانه‌تر مستقل از Policy عمومی (مثلاً کشور تحریمی/حساس همیشه دستی).

### ۵. Human Review Layer (داشبورد)
- صف پیش‌نویس‌های در انتظار تأیید.
- ویرایش/تأیید/رد پیشنهاد AI.
- مدیریت Policy Config (کف قیمت، شرایط پرداخت، ظرفیت) توسط مدیر بازرگانی بدون نیاز به دیپلوی.
- (فاز ۴) نمای مقایسه‌ای چند تأمین‌کننده برای واردکننده.

### ۶. Data Layer
موجودیت‌های پیشنهادی اولیه (برای طراحی دیتابیس در فاز ۰/۱):
- `Contact` — خریدار/تأمین‌کننده خارجی (نام، شرکت، کشور، زبان ترجیحی، کانال).
- `Thread` — یک مکالمه با یک Contact + مرحله فعلی + خلاصه.
- `Message` — پیام تکی داخل thread (خام + ترجمه/خلاصه در صورت نیاز).
- `PolicyConfig` — سیاست‌های شرکت (نسخه‌دار، قابل ویرایش).
- `Catalog/Pricing` — لیست محصولات و قیمت پایه.
- `ProformaDraft` — پیش‌نویس پیش‌فاکتور تولیدشده در فاز‌های بعد.
- `AuditLog` — هر تصمیم AI + اقدام انسانی مرتبط.

### ۷. Integrations (فاز‌های بالاتر)
اتصال به CRM/ERP موجود شرکت برای خواندن کاتالوگ/قیمت واقعی و نوشتن سفارش نهایی — طراحی به‌صورت پلاگین/adapter تا وابسته به یک CRM خاص نشویم.

## پشته فنی پیشنهادی (قابل تغییر بر اساس تیم فنی)
- **Backend**: یک سرویس API متمرکز (مثلاً Python/FastAPI یا Node/NestJS) که Conversation Engine، Policy Engine و Orchestrator را serve می‌کند.
- **LLM Layer**: انتزاع مستقل از provider (پرامپت‌ها + policy injection جدا از مدل انتخابی) تا امکان تعویض مدل بدون بازنویسی منطق کسب‌وکار وجود داشته باشد.
- **صف/زمان‌بندی**: یک job queue ساده برای Follow-up Scheduler (مثلاً cron + صف پیام).
- **دیتابیس**: رابطه‌ای (Postgres) برای Contacts/Threads/Orders + یک لایه ذخیره‌سازی متن پیام‌ها.
- **داشبورد**: یک SPA سبک برای Human Review Layer.

---

## نکات امنیتی و حریم خصوصی
- داده مکالمات تجاری حساس است — دسترسی مبتنی بر نقش (مدیر بازرگانی، عضو تیم فروش) الزامی است.
- Policy Config (کف قیمت، حاشیه سود) باید محدود به نقش‌های مجاز باشد، نه کل تیم.
- اتصال به کانال‌های پیام‌رسانی (واتساپ بیزینس API، ایمیل) باید از کلید/توکن رسمی و امن استفاده کند؛ هیچ اسکرپینگ غیررسمی یا دور زدن API انجام نمی‌شود.
